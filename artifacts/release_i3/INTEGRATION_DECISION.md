# System-A Iteration 3 release integration decision

Date: 2026-09-23. Prepared by parent orchestrator for owner review, **not public upload authorization**.

## Outcome

The existing seed-42 Laya checkpoint supports a usable **local experimental fixed-schema classifier**. Recomputed saved-dev metrics and strict CPU package parity justify distributing it for review without further training. The original test attempt was consumed before this task; its descriptive outcome is not a fresh held-out result and cannot validate post-hoc temperature fitting. No new test records were opened or final marker reset. Additional GPU-worker time consumed: **zero**.

Dev selection remains the historical fixed-six macro-F1 rule: seed 42 `0.4453` versus TF-IDF `0.2927`. Its raw NLL `3.4056` is markedly worse than TF-IDF `0.9519`. Diagnosis finds near-certain wrong predictions, especially `read`/`execute` and `edit`/`execute`, dominating NLL. Cross-entropy plus RLCD weighting is a plausible contributor, not a causal conclusion without a controlled run. No further training was justified within the scope of a release from existing checkpoints, especially because the test is already exposed and two classes have no positives.

The prospectively declared release-use rule in `research/30_i3_release_protocol_amendment.md` was met on exploratory grouped dev CV: raw→foldwise temperature NLL `3.4056→1.0503`, Brier `0.5327→0.5017`, unchanged classification; seven actual CPU dev predictions exactly reproduced saved raw probabilities, and actual logit-scaled outputs matched saved-probability scaling to `1.18e-7` maximum. We therefore package **both raw and dev-temperature-scaled outputs**, temperature `6.203483215500731`, with clear non-confirmatory status. Neither output establishes calibrated behavior outside the 20 dev task groups.

The seven historical execution/evaluation defects are prospectively addressed by the integrated runner and tests: one explicit seed per process with lock-before-Torch, atomic per-seed publication, hash-pinned seed fallback consumed by selection, checksum of the exact split bytes before decoding, representative full-accumulation pilot work, running training deadline, and honest timed inference phases. Fresh restored optimizer/scheduler/scaler `state_dict()` trees are compared by structural and tensor-byte identity after loading. The composed synthetic second-seed CLI failure retains the first result, and a synthetic test-file mismatch fails after the mocked marker but before decoding. This **does not retroactively validate** the old pilot projection, old final latency, old decoded test bytes, or historical reload-state booleans. GPU allocator lifetime remains unmeasured.

The final local package under `release/i3/` contains bundle-relative weights, tokenizer, architecture, pinned Laya source/license, exact question/label mappings, optional calibrated view, fixed-input checks, example states, version pins, full-file integrity manifest and model card. An isolated repository-local copy verifies hashes and executes the CPU quickstart without original source paths; seven dev raw predictions match exactly. A 3-warmup/10-sample CPU timing measures the complete public inference call (latest median `301.2 ms`, nearest-rank p95 `309.7 ms`), with cold load separate (`11.39 s`). These are workstation CPU measurements only.

Independent Luna review found no unresolved concrete implementation defect after full-bundle integrity repair. The reviewed SHA-256 manifest is pinned in `RELEASE_FREEZE.md`; final follow-up review of the exact tightened contract is recorded in `INDEPENDENT_REVIEW.md`. Integrated CPU/offline suite: **62/62 passed** (`integration_tests.log`). `scripts/i3_evidence_audit.py` and `scripts/i3_dev_diagnostics.py` provide replayable evidence. One evidence auditor inadvertently opened the already-consumed historical final-result file during its first audit attempt; this was disclosed, not used for candidate/calibration selection, and does not restore fresh held-out status.
