# Experiment 001 Leakage and Shortcut Review

## Adversarial conclusion

**INFERRED:** As specified, Experiment 001 can show task-disjoint imitation inside one Kimi K3/`moonshiner`/`pi` trace distribution, but it cannot yet distinguish semantic control from recipe recognition, step-position priors, or harness-signature imitation. A positive result is not interpretable as semantic control unless every mandatory test below passes. The source `val` split is necessary but not sufficient: it separates trajectories, not recipe templates, harness conventions, or teacher-generated task families.

**VERIFIED:** Protocol 0.2.0 limits its claim to offline one-step cloning “within one coding harness,” excludes cross-harness generalization, uses cumulative prefixes, and retains task plus recent observable history at 512 tokens (`experiments/exp_001/protocol.json`, fields `claim_scope`, `dataset.unit`, `input`, `splits`). Thus harness imitation is currently compatible with the claimed benchmark result, while any broader “semantic control” reading would be unsupported.

## Evidence boundary

**VERIFIED:** The public card says 3,956 rows come from 582 accepted trajectories; row `k` is cumulative through assistant turn `k`; only the final assistant message is the target; runtime plumbing and success boilerplate are normalized; accepted traces are first-success outputs after an `xhigh -> medium -> low` reasoning-effort fallback and deterministic verification plus Codex review. It documents row fields `task`, `lang`, `category`, `split`, `assistant_step`, `assistant_steps`, `target_message_index`, `n_messages`, and `messages`. Source: [dataset card](https://huggingface.co/datasets/greghavens/kimi-k3-coding-and-debugging-traces/blob/main/README.md), inspected 2026-09-20.

**VERIFIED:** The live manifest reports `schema_version: 1`, `row_count: 3956`, and 50 physical `train-*.parquet` shards. Its Arrow schema additionally exposes `source_trajectory_id`, `source_trajectory_sha256`, `domain`, `verifier`, `teacher_runtime`, `teacher_model`, `reasoning_effort`, `provider`, `observed_models`, `model_attested`, `trace_format`, `tools_used`, `derivation`, `original_n_messages`, and nested message fields `role`, `content`, `reasoning_content`, `tool_calls[].function.{name,arguments}`, `tool_call_id`, and `name`. Source: [dataset manifest](https://huggingface.co/datasets/greghavens/kimi-k3-coding-and-debugging-traces/blob/main/dataset-manifest.json), inspected 2026-09-20.

**VERIFIED:** The Hub has one physical dataset split named `train`; protocol train/test semantics depend on each row's `split` field. Confusing the physical split with the semantic field would contaminate evaluation.

**UNKNOWN:** No dataset commit is pinned, the dataset is advertised as actively growing, Viewer examples were unavailable during this review, and full-value distributions have not been profiled. Assertions below that depend on values rather than schema remain unresolved until the separately planned profiler runs. This review does not duplicate that implementation.

## Shortcut ledger

| Shortcut | Adversarial case | Required detection or disposition |
|---|---|---|
| Cumulative prefixes and repeated early states | **VERIFIED:** A trajectory with `N` assistant turns creates `N` overlapping rows. Long trajectories contribute more loss; early messages recur many times. Even when each row supervises only its final target, nearly identical neighboring prefixes let the model recognize a trajectory phase rather than infer control. | **RECOMMENDED, mandatory:** Report rows and loss weight per trajectory, effective sample size, token/Jaccard similarity between adjacent prefixes, and metrics macro-averaged by trajectory and by assistant step. Train one sensitivity run with equal total weight per trajectory or one sampled step per trajectory per epoch. A promotion that disappears is shortcut-dependent. |
| Repeated early states and position priors | **INFERRED:** `assistant_step`, message count, role cadence, and context length can predict edit/test/final phases. `assistant_step` is excluded as a column but recoverable from the rendered dialogue. | **RECOMMENDED, mandatory:** Fit step-only baselines using observable proxies: token count, message count, counts of assistant/tool/user messages, last role, number of prior tool calls, and truncation occurrence. Report bundle accuracy by step and compare against full model. Shuffle history content while preserving role/length skeleton; a small performance drop indicates structural imitation. |
| Task recipes and near-duplicate prompts | **VERIFIED:** Manifest task IDs visibly encode families, including `behavior-dependency-planning-0007`, `-0080`, `-0124`, and language/task forms such as `bash-*`, `py-*`, and `cpp-*`. The card calls `category` a “detailed recipe category” and says task mix comes from a seed-catalog program mapping. Trajectory-disjoint is not recipe-disjoint. | **RECOMMENDED, mandatory:** Normalize task text and IDs; cluster with exact hash, MinHash/character n-grams, and embedding similarity; report cross-split nearest neighbors and label agreement. Derive recipe groups without using test labels, then report leave-recipe-family-out results. Any unresolved cross-split template family must be named and the semantic-control claim withheld. |
| Source split integrity | **VERIFIED:** Protocol groups on `source_trajectory_sha256` and uses row `split=val` as test. **UNKNOWN:** Whether hashes, IDs, task texts, or derivations overlap in actual values. | **RECOMMENDED, mandatory:** Assert one semantic split per hash and ID; zero hash/ID overlap among train/calibration/test; one task ID per split; zero exact canonical trajectory overlap; and no use of physical Hub split as the experimental split. Freeze manifests before rendering or label inspection. |
| Trajectory hashes and identifiers | **VERIFIED:** Both `source_trajectory_id` and `source_trajectory_sha256` exist. Direct inclusion would make prefixes linkable and can encode collection order or shard provenance. Hash-based calibration assignment is safe only outside model inputs. | **RECOMMENDED, mandatory:** Renderer must use an explicit field allowlist, not a metadata denylist. Unit-test that replacing every non-allowed top-level field, shard path, row index, ID, and hash with sentinels leaves rendered bytes identical. Scan rendered text for full hashes, hash substrings, task IDs, shard names, and serialization keys. |
| Category, domain, language, and derivation metadata | **VERIFIED:** `category`, `domain`, `lang`, and `derivation` exist; protocol explicitly excludes only `category` among these named fields. `task` is ambiguous: the card defines it as stable task ID, while protocol says “task text from first user message.” | **RECOMMENDED, mandatory:** Resolve task ID versus first-user content before freezing. Exclude all top-level metadata by allowlist. Train/report metadata-only probes (`category`, `domain`, `lang`, `derivation`, task-ID affixes) as diagnostic upper bounds; never feed them to Laya. Assert none of their serialized keys or values occur from wrapper serialization. |
| Tool ordering and naming | **VERIFIED:** Messages expose function `name`, `arguments`, `tool_call_id`, result `name`, and parallel `tool_calls`; target labels are derived from a to-be-frozen tool-family map. Tool names can directly reveal both next-action families and harness phase. Parallel call order may be arbitrary. | **RECOMMENDED, mandatory:** Report name-only and previous-tool-only Markov baselines; transition matrices; call-set order sensitivity; duplicate-call handling; and tool-family performance after frequency matching. For independent parallel calls, permute call/result order consistently and require invariant labels and near-invariant predictions. Tool-family mapping must be frozen from train/calibration only, with unseen test names mapped by a preregistered rule. |
| Response-only artifacts | **INFERRED:** `RESPOND_OR_FINISH` may be detectable from last-role, absence/presence of tool results, “tests passed” phrases, empty `tool_calls`, message shape, or a final-response serialization convention rather than completion semantics. | **RECOMMENDED, mandatory:** Enumerate response-only turns and compare their role, key presence, null/empty representation, content length, last observation, and truncation status against tool-call turns. Fit a schema-only classifier with content and tool names removed. Canonicalize null/empty containers identically. Scan pre-target text for success/finalization boilerplate and report label lift from each marker. |
| Reasoning/content leakage | **VERIFIED:** Every message can carry both `content` and `reasoning_content`; the final assistant message contains the target. Protocol excludes target and reasoning. Cumulative rows make an off-by-one error fatal. Tool arguments may themselves contain plans or expected next-tool strings. | **RECOMMENDED, mandatory:** For every row assert `messages[target_message_index]` is the last message, is assistant-role, and is absent byte-for-byte and structurally from state. Recursively replace target `content`, `reasoning_content`, tool names, arguments, IDs, and call ordering with unique canaries and assert no canary/token substring enters rendered IDs or tensors. Recursively assert no `reasoning_content` key/value from any message is rendered. Search prior content/arguments/results for verbatim or normalized target tool names and explicit next-step directives; report rather than silently delete causal content. |
| Teacher and harness signatures | **VERIFIED:** `teacher_model`, `teacher_runtime`, `provider`, `reasoning_effort`, `trace_format`, `model_attested`, and `observed_models` exist. All examples share one teacher/harness distribution. | **RECOMMENDED, mandatory:** Sentinel-invariance test all metadata fields. Inventory repeated system prompts, wrapper phrases, role labels, tool schemas, canonical success/error strings, call IDs, and delimiter tokens; measure their mutual information with labels. Run a harness-stripped renderer diagnostic removing non-causal fixed boilerplate. Because no second harness is evaluated, cross-harness validity remains **UNKNOWN** regardless of score. |
| State truncation | **VERIFIED:** The protocol caps input at 512 tokens while retaining task and most recent history. This can systematically expose only the last tool/result and make labels a local transition lookup; it can also cut call/result pairs or leak target-adjacent wrappers. The exact tokenizer/template is unresolved. | **RECOMMENDED, mandatory:** Log original/rendered token counts, dropped message/turn counts, boundary role, split call/result pairs, and truncation rate by label, category, step, and split. Assert target tokens are appended nowhere before truncation. Report metrics separately for untruncated, task-truncated, history-truncated, and boundary-damaged rows. Compare 256/384/512 or message-boundary truncation on calibration; freeze before test. |
| Success filtering and verifier leakage | **VERIFIED:** Only accepted trajectories survive; coding and instruction tasks use deterministic checks and independent Codex acceptance; `verifier` is a field; reasoning effort steps down until first accepted trace. Error-recovery is only 5 trajectories (0.9%) on the card. | **INFERRED:** The model may learn a stereotyped successful recipe and stopping signal, not robust control. Calibration on accepted traces cannot estimate uncertainty under failures. **RECOMMENDED, mandatory:** Exclude `verifier` and `reasoning_effort` by allowlist and sentinel tests; stratify by verifier and effort for diagnostics; disclose that selective execution applies only in-distribution to accepted prefixes. Failure recovery and action optimality remain explicitly unresolved, not positive claims. |
| Label prevalence and teacher policy | **INFERRED:** Bundle exact match may be dominated by common single-tool transitions or finish decisions. Success filtering can amplify deterministic recipes. Agreement with one teacher does not establish semantic correctness. | **RECOMMENDED, mandatory:** Report bundle frequencies, entropy, unique bundles, per-step/per-category prevalence, majority and first-order transition baselines, macro-F1, and trajectory/category macro metrics. Require gains over the strongest structural/Markov diagnostic, not only the currently listed majority and TF-IDF baselines, before using “semantic.” |

## Mandatory automated test suite

All tests operate on the pinned revision and frozen renderer. Any failed assertion is an invalidating leakage finding; distributional diagnostics require an explicit adjudication before training.

1. **Schema and split test:** exact schema snapshot; semantic `split` values only; row/trajectory counts; one split per `source_trajectory_sha256`, `source_trajectory_id`, and `task`; zero train/calibration/test identity overlap; physical Hub split ignored for assignment.
2. **Prefix integrity test:** `assistant_step` is 1-based and monotone within trajectory; `assistant_steps` is constant; `target_message_index == len(messages)-1`; `n_messages == len(messages)`; earlier rows are exact structural prefixes of later rows after documented normalization. Report every exception.
3. **Target isolation canary test:** recursively canary every final-message scalar, render/tokenize, and assert zero canaries or target-only structural tokens in input. Repeat for all `reasoning_content` values.
4. **Renderer allowlist test:** mutate every top-level field except first-user task text and pre-target observable message fields; rendered bytes must remain identical. Specifically cover IDs/hashes, `category`, `split`, `lang`, `domain`, `verifier`, teacher/runtime/provider/effort, attestation, format, tools-used, derivation, counts, and shard/row provenance.
5. **Cross-split duplication test:** exact and normalized task text, task-ID stems, full rendered states, individual messages, long n-grams, and near-neighbor clusters. Emit concrete pairs and label agreement, not only counts.
6. **Structural shortcut test:** evaluate majority, step/length/role-schema-only, task-ID-affix, tool-name-only, previous-tool Markov, task-only TF-IDF, and history-only baselines using identical group splits.
7. **Ordering/id invariance test:** rename `tool_call_id` values randomly; permute independent parallel calls and matched results; canonicalize dictionary/JSON key order. Labels must be identical and predictions must be reported for consistency.
8. **Response artifact test:** compare missing/null/empty `content`, `tool_calls`, `arguments`, and result fields by target mode; scan fixed finish/success/error phrases; test a content-free schema classifier.
9. **Truncation audit:** deterministic tokenizer/template snapshot; no split target spans; complete message-boundary accounting; truncation-conditioned label and metric tables; state hashes computed after rendering and tokenization.
10. **Weighting audit:** row counts and aggregate loss weights by trajectory, recipe cluster, category, step, and bundle; trajectory-macro evaluation plus equal-trajectory-weight sensitivity.
11. **Teacher/harness marker test:** repeated substrings and wrapper tokens ranked by label mutual information; metadata and fixed-boilerplate ablations; no unexplained high-MI marker may remain.
12. **Contamination test:** compare train/test labels for exact and near-duplicate states and tasks; if test examples have train neighbors, report performance both including and excluding the contaminated cluster.

## Hard pilot generalization test

**RECOMMENDED, mandatory:** Add a frozen **recipe-family-held-out plus harness-perturbation challenge set** drawn only from source-train trajectories, preserving the official `val` test seal. Before training, cluster source-train tasks by normalized task-ID stem and task-text similarity; hold out complete clusters, including at least one repeated catalog family such as `behavior-dependency-planning-*`, subject to adequate row and label support. On those same held-out states create a deterministic perturbed view that:

- replaces tool names and matched result names with per-example opaque aliases while preserving a frozen alias-to-family mapping only for scoring;
- randomizes `tool_call_id` strings;
- permutes independent parallel calls and their matched results;
- removes fixed runtime/UI boilerplate identified without labels;
- preserves task content, causal observations, call/result linkage, and labels.

Report original versus perturbed bundle exact match, prediction consistency, and trajectory-macro confidence intervals. **RECOMMENDED acceptance rule:** pre-register a maximum 5-point absolute degradation and require the perturbed challenge to beat all structural baselines. This is feasible without new trajectories or training, and directly attacks recipe IDs, tool spelling/order, call IDs, and harness wrappers. It is still not cross-harness evidence.

## Stop rule

**RECOMMENDED:** Do not describe a passing run as semantic control if any material shortcut above lacks its automated detection, if recipe-held-out/perturbed performance fails its frozen criterion, or if high performance is matched by structural/Markov baselines. Label the outcome “within-harness trace-pattern imitation” instead. Cross-harness control, failed-state recovery, and action optimality remain **UNKNOWN** under Experiment 001 by design.
